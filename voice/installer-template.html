Voice

A vocal channel strip and effects rack with no pitch detection in it: gate, compressor, de-esser, tone, drive, doubler, chorus, tap delay and reverb. Installs both the mono and the stereo plugin. __BUILD_STAMP__ · aarch64 · __SIZE__ bytes

Ready.

This page must be opened from the Dwarf itself, through the device's File Manager. Opened from your own disk the browser will block the request.

Before you press it

  1. Remove any existing Voice block from your pedalboard. mod-ui caches a failed load.
  2. Press the button. Expected answer: {"ok": true}.
  3. Add the block back and redo your control assignments.

Prefer the terminal?

Check what you downloaded first. The browser may have renamed or unpacked the archive, and that failure looks exactly like a broken plugin:

rm -rf /tmp/voice-inst && mkdir -p /tmp/voice-inst
tar xf voice-aarch64.tar.gz -C /tmp/voice-inst
od -An -tx1 -N1 -j4 /tmp/voice-inst/voice.lv2/voice.so
grep -ao 'VOICE_BUILD[A-Za-z0-9_]*' /tmp/voice-inst/voice.lv2/voice.so

The first must print 02 — the ELF class byte, meaning 64-bit. The Dwarf refuses a 32-bit binary with wrong ELF class: ELFCLASS32.

Then send it. On macOS, COPYFILE_DISABLE is not optional: without it the archive carries ._* resource-fork files, lilv mistakes them for bundle directories, and the plugin fails to load.

cd /tmp/voice-inst
COPYFILE_DISABLE=1 tar czf - --exclude='._*' voice.lv2 \
  | ssh root@192.168.51.1 'rm -rf /root/.lv2/voice.lv2 \
      && tar xzf - -C /root/.lv2 \
      && systemctl restart mod-ui'

Confirm what actually landed on the device:

ssh root@192.168.51.1 "grep -ao 'VOICE_BUILD[A-Za-z0-9_]*' /root/.lv2/voice.lv2/voice.so"

Where it lands

Both variants live in one bundle at /root/.lv2/voice.lv2: Voice (1 in, 1 out) and Voice Stereo (2 in, 2 out). There is no web UI in the bundle, so mod-ui draws its own from the descriptor - every control is there, and there is no template to go wrong.
