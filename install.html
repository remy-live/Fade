Crossfade between two inputs, so a delay tail rings out instead of being chopped. FADE_BUILD1_AARCH64_20260901 · aarch64 · 10988 bytes

Ready.

This page must be opened from the Dwarf itself, through the device's File Manager. Opened from your own disk the browser will block the request.

Before you press it

  1. Remove any existing Fade block from your pedalboard. mod-ui caches a failed load.
  2. Press the button. Expected answer: {"ok": true}.
  3. Add the block back and redo your control assignments.

Prefer the terminal?

Check what you downloaded first. The browser may have renamed or unpacked the archive, and that failure looks exactly like a broken plugin:

rm -rf /tmp/fade-inst && mkdir -p /tmp/fade-inst
tar xf fade-aarch64.tar.gz -C /tmp/fade-inst
od -An -tx1 -N1 -j4 /tmp/fade-inst/fade.lv2/fade.so
grep -ao 'FADE_BUILD[A-Za-z0-9_]*' /tmp/fade-inst/fade.lv2/fade.so

The first must print 02 — the ELF class byte, meaning 64-bit. The Dwarf refuses a 32-bit binary with wrong ELF class: ELFCLASS32.

Then send it. On macOS, COPYFILE_DISABLE is not optional: without it the archive carries ._* resource-fork files, lilv mistakes them for bundle directories, and the plugin fails to load.

cd /tmp/fade-inst
COPYFILE_DISABLE=1 tar czf - --exclude='._*' fade.lv2 \
  | ssh root@192.168.51.1 'rm -rf /root/.lv2/fade.lv2 \
      && tar xzf - -C /root/.lv2 \
      && systemctl restart mod-ui'

Confirm what actually landed on the device:

ssh root@192.168.51.1 "grep -ao 'FADE_BUILD[A-Za-z0-9_]*' /root/.lv2/fade.lv2/fade.so"

Removing the web UI, keeping the plugin

ssh root@192.168.51.1 'cd /root/.lv2/fade.lv2 && rm -rf modgui modgui.ttl \
  && printf "@prefix lv2:  <http://lv2plug.in/ns/lv2core#> .\n@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .\n\n<http://remy-live.github.io/lv2/fade>\n    a lv2:Plugin ;\n    lv2:binary <fade.so> ;\n    rdfs:seeAlso <fade.ttl> .\n" > manifest.ttl \
  && systemctl restart mod-ui'
